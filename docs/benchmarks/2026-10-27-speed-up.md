# 出力のバイト列を変えない高速化の前と後（[ADR 0011](../adr/0011-speed-up-without-changing-bytes.md)）

[ADR 0011](../adr/0011-speed-up-without-changing-bytes.md) の「測定の記録」の節が求める計測の記録である。
同じ PDF を、高速化の前と後の shem で描き、出力が同じであることと、時間を比べた。
2026-10-27 に作り、コミットした後は変更しない。

## 対象

- PDF：[2026-10-27-parallel-render.md](2026-10-27-parallel-render.md) と同じもの（Golem の `kanikosen` の fixture を Golem の 1254092a で組んだ 129 ページ、SHA-256 は `6dc0d3fdff93f89c436a3764be91e0385993d740c5b2c3198e6ced5918fc192c`）。
- 解像度は 150 dpi。

## 環境

- 計算機：Apple M1 Max（10 コア）、メモリ 64GB、macOS 27.0。
- 前：impl/0011-speed のブランチの起点（`9e0f9c7`、[ADR 0009](../adr/0009-render-pages-in-parallel.md) と [ADR 0010](../adr/0010-diff-images.md) まで）を `cargo build --release` で作ったもの。
- 後：この記録を加えたコミット（親は `9e0f9c7` から続く impl/0011-speed のブランチ）を同じく作ったもの。
- 方法：毎回、空の出力のディレクトリに `shem render --dpi 150 [--jobs 1] <PDF> <出力>` を実行し、`/usr/bin/time -p` の real を記録した。前と後を交互に 3 回ずつ走らせた。
- 段階ごとの時間は、ライブラリの関数を呼ぶ作業用のプログラム（リポジトリに入れていない）で、全ページの検査、全ページの描画、全ページの PNG への書き出しを順に測った。前は `check_page` と `render_page` を、後は一つの `FontCache` を共有する `check_page_with` と `render_page_with` を呼んだ。

## 出力が同じであること

- 前と後で 129 ページを PNG と PPM で描き、`diff -r` で、すべてのファイルが同じバイト列だった。
- `tests/golden/` のゴールデン（11 個の PNG）は、作り直さずに通った。

## 結果

`--jobs 1`：

| 回 | 前（秒） | 後（秒） |
|---|---|---|
| 1 | 16.30 | 7.49 |
| 2 | 16.28 | 7.52 |
| 3 | 16.35 | 7.47 |
| 中央値 | 16.30 | 7.49 |

`--jobs` の既定値（10）：

| 回 | 前（秒） | 後（秒） |
|---|---|---|
| 1 | 2.26 | 1.15 |
| 2 | 2.29 | 1.08 |
| 3 | 2.27 | 1.25 |
| 中央値 | 2.27 | 1.15 |

段階ごと（一つのスレッド、3 回の中央値）：

| 段階 | 前（ミリ秒） | 後（ミリ秒） |
|---|---|---|
| 全ページの検査 | 2725 | 542 |
| 全ページの描画 | 5173 | 2502 |
| 全ページの PNG への書き出し | 8692 | 4403 |

- 前の段階ごとの値は、前の版で 3 回測ったもの（検査 2700、2725、2801、描画 5441、5173、5149、PNG 8692、8710、8571）の中央値である。
- 検査の時間の減りは、主にフォントを一度だけ読むようにしたことによる。描画の時間の減りは、フォントとグリフのアウトラインの使い回しと、セルを `Vec` に積むようにしたことによる。PNG の時間の減りは、フィルタの選び方と Deflate の一致の比べ方による。どの変更がどれだけ効いたかは、変更ごとに分けて測っていない。
