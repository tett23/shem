# ADR 0023: 線の継ぎ目の miter の点を、線の方向から求めて上限の中にとどめる

ステータス: 採択（未実装）

## 文脈

[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) は、キャンバスの外の曲線の平坦化を省くと決めた。
`Tr` が 2 の字では、線の多角形が曲線から `16 · half + 16` の余白に収まることを前提に、余白の外の部分の曲線を一本の線分に置き換える。
その前提の根拠は「継ぎ目の miter が頂点から `10 · half`（上限 10）の範囲にあり、丸めの誤差は数単位」という一文だった。

[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の実装を任せた Fable のエージェントが、この前提の反例を見つけた（2026-11-08）。
40 × 30 画素のキャンバスで、`half = 128` の線を、キャンバスの上（余白の外）の小さな曲線に引く。
旧の平坦化は 6 点になり、その一つの頂点の継ぎ目の miter の点が、頂点から 5,461 単位（`42.7 · half`）離れた位置に飛ぶ。
その点はキャンバスに届き、main は 5 画素（不透明度 1）を描く。
平坦化を省いたブランチは何も描かず、出力のバイト列が違う。
手元でも、この曲線を `Tr 2` の字にした 1,077 バイトの PDF を 72 dpi で描き、main とブランチの PPM が違うことを確かめた。
エージェントの乱数の探索では、キャンバスの上に置いた小さな曲線 200 万本のうち 28 本で画素が違い、`half = 2^20` では継ぎ目の点が頂点から 4,200 万単位飛ぶ例もあった。

飛ぶ理由は、miter の点の求め方にある（[src/raster.rs:736](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster.rs#L736) の `join`）。
今のコードは、二つの区間の法線 `n1` と `n2` を、それぞれ長さ `half` に丸めた整数のベクトルにする。
次に、頂点から `n1` と `n2` だけずらした二本の直線の交点を、`det = n1 × n2` で割って求める。
ほぼ同じ向きの短い区間では、`n1` と `n2` がほとんど同じで、丸めの誤差が差の大部分を占める。
`det` は丸めの誤差で決まる小さな値（反例では −3）になり、交点が遠くへ飛ぶ。
本来の miter の点は、同じ向きに近いほど頂点の近く（`half` の近く）にあるので、この飛びは丸めの誤差による見た目の欠陥である。

同じ形の `join` が、参照の実装（[src/raster/reference.rs:359](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster/reference.rs#L359)）にもある。

fixture では、`sample.pdf` と `sample-marks.pdf` が `Tr 2` を使う（内容のストリームの中に 2 か所ずつ）。
この二つは、miter の点の丸めが変われば、出力のバイト列が変わりうる。
`kanikosen.pdf`、`figures.pdf`、`truetype.pdf` は `Tr 2` を使わない。
画像と図版の箱の十字は、二本の線分が交わらない二つのサブパスなので、継ぎ目を作らない。

## 実装すること

### miter の点

- miter と bevel の選び方（`within_limit`、`100 · dot + 98 · lens >= 0`）は変えない。区間の向きの外積が 0 なら継ぎ目を作らないことも、変えない。
- miter の点を、丸めた法線の交点ではなく、二つの区間の方向から次の式で求める。`d1` と `d2` は区間の方向、`sign` は今と同じく外積の符号から決める向きとする。

  ```
  m = half · (N1 + N2) / (1 + cos θ)
  ```

  `N1` と `N2` は単位の法線、`θ` は二つの区間の方向の間の角である。
  `|m| = half / cos(θ/2)` で、`cos(θ/2)` は PDF の miter の比の逆数（`sin(φ/2)`、`φ` は区間の間の角）なので、上限 10 の中の miter では `|m| ≤ 10 · half` になる。
- 式は、次の整数の計算で求める。
  - 方向 `d` の成分の絶対値の大きいほうが 2^28 以上なら、2^28 未満になるまで二つの成分を同じだけ右に算術シフトする。これを `e` とする（向きの誤差は 2^−27 以下）。
  - `L = isqrt((e.x² + e.y²) · 2^64)`（`|e| · 2^32` の切り捨て、2^61 未満）
  - `P = sign · (−e.y, e.x)`
  - `num = P1 · L2 + P2 · L1`（絶対値が 2^90 未満）、`den = L1 · L2 + (e1 · e2) · 2^64`（2^123 未満）
  - `m = div_round(half · num, div_round(den, 2^32))`（成分ごと）。`den` が 0 以下か、`half · num` が i128 に収まらなければ（`half` が 2^35 以上なら起こりうる）、bevel にする。
- 継ぎ目の多角形は、今と同じく `[v, v + n1, v + m, v + n2]`（bevel は `[v, v + n1, v + n2]`）とし、`n1` と `n2` は今と同じく丸めた法線とする。
- 参照の実装の `join` も、同じ式に変える。参照の実装は、[ADR 0013](0013-fewer-allocations-for-musl-threads.md) からの書き換えが出力を変えないことを確かめる比較の相手なので、出力の決まりの変更は両方に入れる。

### [ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) との関係

- この ADR の後では、miter の点は頂点から `16 · half` 以内にある（テストで確かめる）。継ぎ目の多角形の点は、頂点から `max(half, |m|) + 2` 以内なので、[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の余白 `16 · half + 16` の論証が成り立つ。
- [ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) のステータスを「採択（未実装）→`Tr 2` の字の余白の前提はADR 0023」にする。[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) は、この ADR を実装した後に実装する。

### 文書と画像

- 仕様の「描画」の節の線の項に、miter の点の求め方を書く。
- `sample.pdf` と `sample-marks.pdf` の画像が変われば、ゴールデンと、`tests/fixtures/golem/operators.sha256` などのバイト列の一覧を作りなおす。変わった画素を `shem diff` で数え、差分の画像を見て、変わったのが `Tr 2` の字の継ぎ目だけであることを確かめ、プルリクエストに書く。

## 実装しないこと

- miter と bevel の選び方、線端（butt）、線の幅の求め方を変えること。
- 法線の丸め（区間の四角形の点）を変えること。区間の四角形は頂点の継ぎ目と違い、`det` で割らないので飛ばない。
- 丸い継ぎ目（round join）や、PDF の `j`、`M` の演算子。v0.1 の範囲の外である（[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md)）。
- 線の多角形の点の i32 への折り返し。`Tr 2` の字は、[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の検査で扱う。

## テスト設計

どのテストも、実装の前に書き、今のコードで失敗することを確かめてから実装する。

### miter の点の大きさ

- 乱数で作った二つの方向と幅で、`join` が miter を作るとき、miter の点の頂点からの距離の 2 乗が `(16 · half)^2` 以下である。方向は、長さ 1 から 300 単位の短いもの、ほぼ同じ向きのもの（外積が 1 から 10 のもの）、成分が 2^31 に近い長いものを含め、幅は 1 から 2^20 単位とする。今のコードは、ほぼ同じ向きの短い方向で失敗する。
- 反例の継ぎ目（方向 (60, 62) と (59, 61)、`half = 128`）の miter の点が、頂点から `16 · half` 以内にある。今のコードは 5,461 単位になる。

### miter の点の値

- テストの中に、成分の絶対値が 2^16 未満の方向について、miter の点を `half · 2^−28` の精度で求める参照を置く。参照は、長さを `isqrt(len2 · 2^64)`、`(N1 + N2) / (1 + cos θ)` を 2^28 倍の整数で求め、`half` を掛けて丸める。乱数の方向（2^16 未満）と幅（1 から 2^20 単位）で、`join` の miter の点の各成分が、その参照と 2 単位以内で一致する。
- 直角（方向 (256, 0) と (0, 256)、`half = 128`）の miter の点の、頂点からのずれの成分の絶対値が、どちらも 128 である。

### 選び方と出力

- miter と bevel の選び方が、今のコードと同じである（乱数の方向で、多角形の点の数を比べる）。
- 参照の実装との比較のテスト（[ADR 0013](0013-fewer-allocations-for-musl-threads.md) から）を、そのまま通す。
- 反例の PDF を 72 dpi で描いた画像が、白紙である。
- `kanikosen.pdf`、`figures.pdf`、`truetype.pdf` を 72、97、150、300 dpi の PPM と 150、300 dpi の PNG で描き、main と同じバイト列であることを確かめる。`sample.pdf` と `sample-marks.pdf` は、変わった画素の数と差分の画像を記録する。

## トレードオフ

- `Tr 2` の字を含むページの画像が、継ぎ目の画素で変わりうる。v0.1.0-rc6 の画像と比べている利用者には、プレリリースの変更として知らせる。
- miter の点の計算に `isqrt` が二回と i128 の割り算が要り、今より遅い。継ぎ目は `Tr 2` の字と箱の十字にしかなく、fixture では描画の時間に効かない見込みである。実装の後に、`sample.pdf` の時間を測って確かめる。
- 方向を 2^28 未満にシフトするので、とても長い区間の向きの精度は 2^−27 になる。miter の点の誤差は `half · 10 · 2^−27` 程度で、`half` が 2^20 でも 0.1 単位より小さい。

## 精度の検討

整数の計算の精度は、Python の一時的なスクリプトで、60 桁の十進数で求めた miter の点と比べて決めた（2026-11-08、スクリプトはコミットしていない）。
方向は、長さ 300 単位までの短いもの、ほぼ同じ向きのもの、成分が 2^32 までの長いものを混ぜた 10 万組とし、幅は 1、128、2^20 と、1 から 2^20 の乱数とした。

| 方向のシフト | 長さの倍率 | 最悪のずれ |
|---|---|---|
| 2^24 未満 | 2^16 | 466 単位（幅 713,182、方向 (−148, 173) と (2, −4)） |
| 2^24 未満 | 2^32 | 6.8 単位 |
| 2^28 未満 | 2^32 | 0.79 単位 |

この ADR の最初の案は一行目の精度で、テスト設計の「2 単位以内」を満たさないことが、実装の前の確認でわかった。
ADR を push する前だったので、三行目の精度に書き直した。
三行目の精度でも、miter の点の頂点からの距離は、30 万組で最大 `10.3 · half` だった。
