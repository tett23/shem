# ADR 0022: キャンバスの外の線分と曲線に、バイト列を変えずに時間をかけない

ステータス: 採択

## 文脈

2026-11-08 の脆弱性診断（[docs/audit/2026-11-08-vulnerability-assessment.md](../audit/2026-11-08-vulnerability-assessment.md)）の所見 6 で、キャンバスの外の図形の塗りに、座標の幅に比例する時間がかかることがわかった。
`MediaBox [0 0 100 100]` のページで `0 0 2000000 2000000 re f` を 20 回塗る 933 バイトの PDF に、2.8 秒かかる。
遠い制御点の `c` を 100 個並べた 539 バイトの PDF には、18 秒かかった。

時間がかかる理由は二つある。

一つ目は、線分の交点である。
`render_line`（[src/raster.rs:394](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster.rs#L394)）は、線分がまたぐすべての行の交点と、各行の中のすべての列の交点を求め、セルごとに `add` を呼ぶ。
キャンバスの外のセルは、`add` の中で捨てる（密な格子）か、集めてから掃き出しで捨てる（疎なセル）。
捨てるセルにも交点の計算がかかり、疎なセルでは捨てるセルの分だけメモリも使う。
上の矩形の一辺は 400 万行をまたぐので、キャンバスが 208 行でも 400 万回の計算になる。

二つ目は、曲線の平坦化である。
`flatten_curve_into`（[src/raster.rs:167](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster.rs#L167)）は、制御点の二階差分が 1/16 画素以下になるまで、深さ 16 まで二分する。
制御点が遠いと、キャンバスの外の部分も深さ 16 まで分け、一つの `c` が最大 2^16 個の点になる。
点はパスに貯まり、それぞれが一つ目の理由の線分になる。

キャンバスの外のセルが画素にどう効くかは、`coverage_with`（[src/raster.rs:508](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster.rs#L508)）の注釈のとおりに決まっている。

- キャンバスの行の外（行が 0 未満か、高さ以上）のセルは、どの画素も変えない。
- キャンバスの右（列が幅以上）のセルは、どの画素も変えない。
- キャンバスの左（列が 0 未満）のセルは、その行の cover に足されるだけで、area は使われない。

したがって、この三つの性質を保つかぎり、外のセルを求めずに済ませても画素は変わらない。
この ADR は、その形で計算を省き、出力のバイト列を変えないことを決める。

## 実装すること

### 記号

- キャンバスの幅と高さを `w` と `h` 画素とし、装置の空間の単位（画素の 1/256）で `W = 256 w`、`H = 256 h` とする。
- 線分と曲線の点の座標は、今と同じく装置の空間の i32 である。

### 線分の行

- `render_line` に、キャンバスの行の範囲（0 以上 `H` 以下）と、列の上限 `W` を渡す。
- 線分を行で分けるとき、`crossings(y0, y1)` のうち 0 以上 `H` 以下の交点だけを `interpolations` に渡す。その外の区間は、どの画素も変えないので、`render_row_piece` に渡さない。
- 範囲の最初の交点の x は、`interpolations` が最初の交点を割って求めるので、今の値と同じである。次からは持ち越すので、[ADR 0020](0020-carried-crossings-for-every-i64.md) のとおり、交点ごとに割った値と同じである。
- 線分の端点が範囲の中にあれば、端点から最初の交点までと、最後の交点から端点までの区間は、今と同じく `render_row_piece` に渡す。

### 線分の列

- 行の中の区間を列で分けるとき、x が `W` 以上の側の交点を求めない。その側のセルは画素を変えない。
- x が 0 以下の側は、区間ごとのセルを求めずに、その側の高さの和（その側の端の y の差）を、列 −1 の一つのセル（area は 0）として `add` に渡す。区間ごとの高さの和は、隣の区間の y の差の和なので、端の y の差と等しい。その端の y は、x = 0 の交点の y で、今と同じく `interpolations` で求め、行の y の範囲にそろえる（`clamp`）。
- 密な格子と疎なセルのどちらでも、列 −1 のセルは cover だけが使われるので、画素は今と同じである。

### 曲線の平坦化

- 曲線を二分する途中で、部分の曲線の四つの制御点が次のどれか一つの領域にすべて入るなら、それ以上分けずに、部分の曲線の終点だけを出す（部分の曲線を、端点を結ぶ一本の線分に置き換える）。`m` は余白で、後で決める。
  - 上：y がすべて `−m` 以下
  - 下：y がすべて `H + m` 以上
  - 右：x がすべて `W + m` 以上
  - 左：x がすべて `−m − 1` 以下
- 曲線は制御点の凸包の中にあり、置き換えた線分も同じ凸包の中にあるので、どちらも同じ領域の中にある。上、下、右の領域の線分は、どの画素も変えない。左の領域の線分が行に足す cover の和は、線分の列の始点と終点の y だけで決まる（行の y の範囲にそろえた終点の y から、始点の y を引いたもの）。置き換える前の線分の列と置き換えた線分は、始点と終点が同じなので、どの行にも同じ cover を足す。
- 塗るだけのパス（ページの内容の `f` と、`Tr` が 0 の字）は、`m = 0` とする。
- `Tr` が 2 の字は、塗った後に同じパスの線を描くので、`m = 16 · half + 16` とする（`half` は線の幅の半分を装置の単位で表した値）。線の多角形は、区間の四角形が区間から `half`、継ぎ目の miter が頂点から `10 · half`（上限 10）の範囲にあり、丸めの誤差は数単位である。余白の外の部分の曲線の線の多角形と、その端点の継ぎ目は、どれも同じ領域の中にある。左の領域の多角形は一つずつ閉じているので、どの行にも足す cover の和は 0 である。
- 平坦化を、キャンバスの大きさと余白を受け取る形にする。キャンバスを渡さない今の `Path::curve_to` は、ライブラリの API として残す。

### `Tr 2` の字の点の範囲

- `Tr` が 2 の字は、アウトラインのすべての点（制御点を含む）を装置の空間に写した x と y の絶対値に余白 `m` を足した値が、`2^31 − 1` 以下であることを、検査で確かめる。超えれば `glyph stroke outside the range of coordinates` のエラーにする。
- 今のコードは、線の多角形の点を作るときに i64 から i32 へ黙って折り返しうる（[src/raster.rs:709](https://github.com/tett23/shem/blob/4ab16a6deb19ec403aa438b5e7540a5eec6fd0f6/src/raster.rs#L709)、診断の軽微なもの）。この検査を通った字は、余白の中で折り返さないので、平坦化を省いても線の多角形の画素は変わらない。
- 検査は描く前に行うので、[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) のとおり、出力を一つも書かないうちに止まる。

### 文書

- 仕様の「描画」の節に、キャンバスの外の線分と曲線の扱いと、`Tr 2` の字の点の範囲を書く。
- 仕様の「決定性」の節に、キャンバスの外の計算を省いても画素が変わらない理由を書く。

## 実装しないこと

- 画像と図版の箱の十字の線の点の範囲の検査。十字は線分だけで曲線を含まないので、この ADR の省き方に関わらない。折り返しの仮説は再現していないので、ここでは扱わない。
- ページの描画の時間の上限。キャンバスの中に描く量（塗りの回数とキャンバスの大きさの積）には比例したままである（[ADR 0021](0021-limits-on-hostile-input.md) の「実装しないこと」）。
- 曲線の平坦化の深さの上限（16）と、平坦さの基準（1/16 画素）を変えること。キャンバスの中の曲線の点は、今と同じである。
- キャンバスの外の部分を、一般の多角形の切り取り（Sutherland–Hodgman など）で取り除くこと。切り取りは新しい点を作るので、cover と area の丸めが変わり、出力のバイト列が変わりうる。

## テスト設計

どのテストも、実装の前に書き、今のコードで失敗することを確かめてから実装する。
画素の比較の相手は、v0.1.0-rc2 のラスタライザ（`src/raster/reference.rs`）で、計算を省かない。

### 計算の量

- 100 × 100 画素のキャンバスで、(−2^30, −2^30) から (2^30, 2^30) への線分の `render_line` が `add` を呼ぶ回数が、`4 (w + h) + 8` 以下である。今のコードでは 2^23 回を超える。
- 制御点が ±2^30 にあり、キャンバスを横切る曲線の平坦化の点の数が、4,096 以下である。キャンバスの外にだけある曲線の点の数は 1 である。今のコードは、どちらも 1,000 個を超える（制御点が ±2^30 の例で、横切るもので 14,013 個、外にだけあるもので 6,111 個だった）。
- `0 0 2000000 2000000 re f` を 200 回塗る PDF の描画で、`add` を呼ぶ回数（テストのための数え方で測る）が、200 × `4 (w + h) + 8` 以下である。

### 画素

- 乱数で作ったパスの覆いが、参照の実装の覆いと同じである。パスは、線分と曲線を混ぜ、座標を i32 の全範囲、キャンバスの近く（±4 画素）、キャンバスの辺の上（x = 0、y = 0、x = `W`、y = `H`）から選ぶ。キャンバスは、密な格子に入るもの（2^16 セル以下）と入らないもの（疎なセル）の両方にする。nonzero と偶奇の両方の規則で確かめる。
- 左の領域を何度も行き来する曲線（S 字で x < 0 の側を往復するもの）、領域の境目をまたぐ曲線、端点が境目の上にある曲線を含める。
- `Tr` が 2 の字に相当するパスで、線の多角形の覆いが、参照の実装の `stroke` で作った覆いと同じである。線の幅は、1 単位から 2^20 単位まで選ぶ。
- 既存のテストを、そのまま通す：ゴールデン、kanikosen のバイト列の一覧、[ADR 0019](0019-faster-deflate-sweep-and-operands.md) と [ADR 0020](0020-carried-crossings-for-every-i64.md) の交点のテスト。

### `Tr 2` の字の点の範囲

- `Tr 2` で、余白を足すと i32 を超える位置に字を置いた PDF は、検査で文のとおりのエラーになり、出力のディレクトリにファイルが一つもできない。
- 余白を足しても収まる位置の字は、今と同じ画素で描ける。

### 確かめ方

- 実装の後、fixture の五つの PDF を 72、97、150、300 dpi の PPM と 150、300 dpi の PNG で描き、main と同じバイト列であることを確かめる。
- kanikosen の 300 dpi の PPM と 150 dpi の PNG の `--jobs 1` の時間が、main と変わらないことを確かめる。平坦化の途中の領域の判定は、部分の曲線ごとに八つの比較である。
- 診断の所見 6 の二つの PDF（矩形 200 個と曲線 100 個）が、それぞれ 0.5 秒以内に描けることを、手元で測る。

## トレードオフ

- 画素が変わらないことは、外のセルの三つの性質と、凸包と cover の和の論証に頼る。論証が誤っていれば、キャンバスの端の画素が変わりうる。乱数の比較と fixture のバイト列で確かめるが、すべての入力を試すわけではない。将来、外のセルの扱い（たとえば左のセルの area を使う塗りの規則）を変えるときは、この ADR の前提を見なおす。
- `render_line` と平坦化がキャンバスの大きさを受け取るので、ラスタライザの関数の引数が増える。
- `Tr 2` の字は、今は描ける入力（i32 の端の近くの字）の一部が、エラーになる。どれも線の多角形の点が折り返しうる入力で、Golem の出力にはない。
- キャンバスの外にだけある図形は、ほぼ時間がかからなくなる。キャンバスを横切る図形は、キャンバスの中の行と列の数に比例する時間がかかり、座標の幅にはよらない。
