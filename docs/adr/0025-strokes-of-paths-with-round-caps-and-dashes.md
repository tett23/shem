# ADR 0025: ページのパスの線（`l`、`S`）と、丸い線端（`J`）と破線（`d`）

ステータス: 採択→円板の作り方、終点の点、奇数の配列の周期、テストの許容幅は[ADR 0026](0026-corrections-to-round-caps-and-dashes.md)

## 文脈

Golem の [ADR 0271](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/docs/adr/0271-paragraph-backgrounds-and-borders.md) は、段落の囲みの角を丸められるようにし、丸めた角を持つ囲みの枠を、パスの線（`S`）で描くと決めた。
破線は `d` のダッシュの配列で、点線は丸い線端（`1 J`）と長さ 0 のダッシュで描く。
Golem の Writer は、この線を次の形で書く（Golem の origin/main の 7e8fe7d3 で調べた。[Writer.hs:468-479](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-pdf/src/Golem/Pdf/Writer.hs#L468-L479)、[Writer.hs:525-527](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-pdf/src/Golem/Pdf/Writer.hs#L525-L527)）。

```
q
<c> <m> <y> <k> k <c> <m> <y> <k> K
<幅> w [1 J] [[<ダッシュ> <間>] 0 d]
<x> <y> m
<x> <y> l            （辺）
<x1> <y1> <x2> <y2> <x> <y> c   （丸めた角の四分円）
...
[h] S
Q
```

- `J` は、丸い線端のときだけ `1 J` を書く。`d` は、破線と点線のときだけ書き、配列は二つの数、位相は常に 0 である。
- 線の種類ごとの値は、[Box.hs:247-252](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-typeset/src/Golem/Typeset/Box.hs#L247-L252) で決まる。実線は `d` を書かず、破線は `[<ダッシュ> <間>] 0 d`、点線は `1 J [0 <太さ + 間>] 0 d` である。
- 枠は `q` と `Q` の中に書くので、`J` と `d` は枠の後に残らない。
- 囲みの辺が一続きなら閉じたパス（`h S`）、`border-sides` で辺が途切れるなら、続く辺ごとに開いたパス（`S`）になる。
- 角を持たない部分（`border-radius` が 0）の枠は、今までどおり `re f` の帯で描く。
- 縦組みでも、CTM は `D` に平行移動を掛けたもので、角を保つ。

shem は、[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) の表にない `l`、`S`、`J`、`d` をエラーにする。
線を描く処理は [ADR 0003](0003-paths-fill-stroke-and-antialiasing.md) で持っているが、線端は butt、角は miter に固定で、破線を持たない。
そのため、Golem は見た目の回帰テストの見本（`specimens`）の角丸のコラムを背景だけにしている（[specimens/horizontal/style.toml:100-112](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-driver/test/fixtures/specimens/horizontal/style.toml#L100-L112)）。
2026-11-10 に、tett23 は、shem が `l`、`S`、`J`、`d` を読み、Golem が ADR 0271 のとおり角丸の枠を線で描けるようにすると決めた。

この ADR は、[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) の範囲を、Golem の Writer が書くこの形まで広げる。
CLAUDE.md の「範囲を広げるとき（Golem への追従）は ADR から始める」に従う。

## 実装すること

### 演算子

[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) の表に、次の行を加える。

| 分類 | 演算子 | 被演算子 | 置ける場所 |
|---|---|---|---|
| グラフィックスの状態 | `J` | 整数 1（0 と 1 だけ） | ページと文字のオブジェクトの中（`w` と同じ） |
| | `d` | 配列 1、数 1 | 同上 |
| パス | `l` | 数 2 | パスの途中（`c` と同じく、現在の点が要る） |
| | `S` | なし | パスの塗り（`f` と同じ） |

- `J` の 2（square）は、`unsupported J 2` のエラーにする。Golem の Writer は書かないからである。0 から 2 の外の整数は、壊れた入力として `malformed J <値>` のエラーにする。
- `d` の配列の要素は数で、どれも 0 以上とする。空でない配列の要素がすべて 0 なら、ISO 32000-1 の 8.4.3.6 のとおり壊れた入力として `malformed d` のエラーにする。空の配列は実線を表す。位相は 0 以上の数とする。負の数と、数でない要素はエラーにする。
- `l` は、現在の点から点 (x, y) への線分を、現在の部分パスに加える。点は `m` と同じく CTM で装置の空間に写して丸める。
- `S` は、現在のパスを線の色（`K`）で線として描き、パスを空にする。`h S` で閉じた部分パスは閉じたまま、`h` のない部分パスは開いたまま描く（`f` と違い、開いた部分パスを閉じない）。
- `J` と `d` の値は、グラフィックスの状態に入れ、`q` と `Q` で保存と復元をする。初期値は `0 J` と `[] 0 d` である。

### 線端

[ADR 0003](0003-paths-fill-stroke-and-antialiasing.md) の線の作り方（区間の四角形と、継ぎ目の多角形の和を nonzero で塗る）に、丸い線端を加える。

- `0 J`（butt）の線は、今と同じ多角形を作る。`J` と `d` を使わないページの画像は変わらない。
- `1 J`（round）では、開いた部分パス（と、後で述べる破線の一つ一つ）の両端に、端点を中心とし、半径が線の幅の半分 `half` の円板を加える。円板の半分は区間の四角形に重なるので、和集合は半円の線端になる。
- 円板は、原点を中心とする四つの四分円の 3 次のベジエ曲線を、[ADR 0003](0003-paths-fill-stroke-and-antialiasing.md) の平坦化（中点での二分、1/16 画素、深さ 16）で線分の列にした多角形とする。制御点の原点からの距離は `k = div_round(half · 36195, 65536)` とする。36195 は、四分円の中点を円の上に置く係数 `4(√2 − 1)/3 ≈ 0.552285` を 2^16 倍して丸めた値である。
- 一つの `S` の中では、円板の多角形を一度だけ作り、各端点へ平行移動して使う。平行移動は整数の足し算なので、どの端点の円板も同じ形になる。
- 角（`j`）は今と同じく miter（上限 10）とする。

### 長さ 0 の部分パス

ISO 32000-1 の 8.5.3.2 に従う。

- 点が一つの閉じた部分パス（`m h`）と、すべての点が同じ部分パスは、`1 J` なら、その点に円板を描く。`0 J` なら何も描かない。
- 点が一つの開いた部分パス（`m` だけ）は、どちらの線端でも何も描かない。

### 破線

- 破線は、平坦化した後の装置の空間の線分の列の上で、長さを測って切る。部分パスごとに、ダッシュの配列の最初から、位相だけ進めた位置で始める（ISO 32000-1 の 8.4.3.6）。
- 配列の要素の数が奇数なら、配列を二回つないだものとして扱う（`[3]` は `[3 3]`）。
- 長さは、装置の単位（1/256 画素）の 2^−16 を単位とする整数で表す。
  - ダッシュの配列の要素と位相は、利用者の空間の値に、線の幅と同じ拡大率 `sqrt(|det CTM|)` を掛け、この単位に丸める（最近接の偶数への丸め）。
  - 線分 (a, b) の長さは、`isqrt((dx² + dy²) · 2^32)`（切り捨て）とする。`dx` と `dy` は i32 の差なので、2 乗の和に 2^32 を掛けても u128 に収まる。
- 配列の和（周期）が、この単位で 1/16 画素（2^16 · 16）未満なら、`dash pattern shorter than 1/16 pixel` のエラーにする。周期の下限は、一つの線分から生まれる破線の数を、線分の長さの 16 倍（画素の数で）以下に抑えるためである。位相は、周期で割った余りにする。
- 線分の上の距離 t の点は、`a + div_round((b − a) · t, L)`（`L` は線分の長さ、成分ごと）とする。
- 「描く」要素の区間ごとに、その区間の点の列（始まりの点、間にある頂点、終わりの点）を、開いた部分パスとして [線端](#線端) と継ぎ目の規則で線にする。区間の中の頂点には継ぎ目を作り、区間の両端には線端を付ける。
- 長さ 0 の「描く」要素は、`1 J` なら、その位置の円板になる。`0 J` なら何も描かない。
- 閉じた部分パスでも、最後の破線と最初の破線は継がず、どちらにも線端を付ける。

### キャンバスの外

[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の省き方を、ページのパスの線に広げる。

- 曲線の平坦化の余白 `m` は、`c` を読んだときのグラフィックスの状態で決める。パスの構築の途中では `w`、`J`、`d`、`cm` を置けないので、`c` のときの状態は `S` のときと同じである。
  - 実線（空の配列）で CTM が角を保てば、`m = 16 · half + 16` とする。丸い線端の円板は端点から `half` 以内なので、この余白に収まる。
  - 破線なら、平坦化を省かない（キャンバスを渡さない `Path::curve_to` と同じ点の列にする）。省くと、キャンバスの外の曲線の長さが変わり、その後の破線の位置がキャンバスの大きさで変わるからである。
  - それ以外（CTM が角を保たない）は、`m = 0` とする。`S` はエラーになり、`f` の画素は余白によらない（[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md)）。
- 破線を切るとき、両端が同じ一つの外の領域（[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の上、下、右、左。余白は `16 · half + 16`）にある線分は、多角形を作らず、破線の位置だけを進める。その線分で、描いている区間を終える（継ぎ目も線端も作らない）。そこで終えた区間の多角形と、作らなかった多角形は、どれも同じ領域の中にあって閉じているので、画素を変えない。
- 平坦化を省かない破線の曲線は、一つの `c` が最大 2^16 個の点になる。外の線分は破線の位置を進めるだけなので、点の数に比例する時間で済む。

### 検査

[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) のとおり、次のエラーは、画素を描かない検査で見つけ、出力を一つも書かないうちに止める。

- 被演算子の誤り、`unsupported J 2`、`malformed d`
- `S` のときの CTM が角を保たない（今の `unsupported stroke with a CTM that does not keep angles`）
- `S` のときの周期が 1/16 画素未満
- `S` のパスの平坦化した点の x と y の絶対値に、余白 `16 · half + 16` を足した値が `2^31 − 1` を超える。`stroke outside the range of coordinates` のエラーにする。線の多角形の点が i32 で折り返さないためである。

### 文書

- 仕様の「読む PDF の部分集合」の演算子の表と、「描画」の線の項に、この ADR の内容を書く。
- ロードマップの v0.1 の演算子の列に `l S J d` を加える。v1 の候補の「破線、線端と角」を、残る `2 J`、`j`、`M` に直す。
- README に描ける範囲の記述があれば、同じく直す（README.ja.md も訳しなおす）。

## 実装しないこと

- `2 J`（square）、`j`（角の種類）、`M`（miter の上限）。Golem の Writer は書かない。v1 に向けた拡大で、別の ADR で加える。
- `s`（閉じて線を描く）、`B`、`B*`、`b`、`b*`（塗って線を描く）、`f*`、`W`、`n`。Golem のページの内容は書かない（SVG の図版の Form は書くが、v0.1 では箱にする。[ADR 0006](0006-placeholder-boxes-for-images-and-forms.md)）。
- 角を保たない CTM での線。今と同じくエラーにする。
- `Tr 2` の字の線と、画像と Form の箱の十字に、線端と破線を当てること。どちらも今と同じく butt の実線で描く。
- 閉じた部分パスの最初と最後の破線を継ぐこと。
- 一つの `S` の破線の数の上限。周期の下限で、破線の数を描く長さに比例させる。

## テスト設計

どのテストも、実装の前に書き、今のコードで失敗することを確かめてから実装する。

### 演算子の読み

- `l`、`S`、`J`、`d` が、正しい被演算子で通り、被演算子の数か型が違うとエラーになる。
- `0 J` と `1 J` は通り、`2 J` は `unsupported J 2`、`3 J` と `-1 J` は `malformed J` のエラーになる。
- `[] 0 d`、`[3 2] 0 d`、`[0 3] 0 d`、`[3] 1.5 d` は通る。`[0 0] 0 d`、`[-1 2] 0 d`、`[3 2] -1 d`、`[/a] 0 d` はエラーになる。
- `m` の前の `l`、パスの途中の `J` と `d`、文字のオブジェクトの中の `l` と `S` は、エラーになる。
- Golem の Writer のテストの三つの出力（[golem-pdf の test/Main.hs:329-334](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-pdf/test/Main.hs#L329-L334)）を内容に持つ PDF が、エラーなしに通る。
- `q 1 J [3 2] 0 d Q` の後の `S` は、butt の実線になる（`q` と `Q` での復元）。

### 線端

- `0 J` の線の多角形は、今の `stroke_into` と同じである。参照の実装との比較のテスト（[ADR 0013](0013-fewer-allocations-for-musl-threads.md)）を、そのまま通す。
- `1 J` の水平の線分を幅 4 画素で描くと、端点から線分の外に半径 2 画素の半円が付く。端点の外側 2 画素の位置の画素は塗られず、1 画素の位置は塗られる。
- 円板の多角形は、半径 1 から 2^20 単位の乱数で、すべての点の中心からの距離が `half` から 1/16 画素と 2 単位以内である。点の数は 4 の倍数で、x と y の対称（点の集合が軸と対角線で反転して等しい）が成り立つ。
- `1 J` の `m h S` は円板を描き、`0 J` の `m h S` と、どちらの線端の `m S` も何も描かない。

### 破線

テストの中に、有理数で長さを求めて破線を切る遅い参照を置き、破線の区間の端点を比べる。

- 長さ 10 画素の水平の線分に `[3 2] 0 d` を当てると、[0, 3]、[5, 8] 画素の二本になる。位相 1 なら [0, 2]、[4, 7]、[9, 10] になる。
- 奇数の配列 `[3]` は `[3 3]` と同じ画像になる。
- 頂点をまたぐ破線は、頂点に継ぎ目（miter）を持つ。直角に曲がる折れ線で確かめる。
- `1 J [0 3] 0 d` の線分は、3 画素ごとの円板（点）になる。点の数と中心の位置が参照と一致する。
- 部分パスが二つあると、二つ目は配列の最初から位相だけ進めた位置で始まる。
- 閉じた部分パスの破線は、最後の辺も破線になり、始点で継がない。
- 乱数の折れ線（長さ 1 から 2^20 単位の線分）と配列で、破線の区間の端点が参照と 2 単位以内で一致し、区間の長さの和が参照と、線分の数の 2 倍の単位以内で一致する。
- 周期が 1/16 画素ちょうどの配列は通り、1 単位短いとエラーになる。72 dpi と 300 dpi で境目が変わることも確かめる。

### キャンバスの外

- 実線の `S` と、`1 J` の `S` について、[ADR 0022](0022-no-work-for-geometry-off-the-canvas.md) の `outside_tests` と同じ乱数のテストを足す。キャンバスの外の曲線を省いた画像が、省かない画像とバイト単位で同じである。
- 破線の `S` について、外の線分で多角形を作らない画像が、すべての線分の多角形を作る画像と同じである。
- 遠い制御点の `c` を 100 個並べ、`[1 1] 0 d S` で描く PDF が、1 秒以内に描ける。
- 点の座標に余白を足すと `2^31 − 1` を超えるパスの `S` は、`stroke outside the range of coordinates` のエラーになり、三ページの三ページ目にあるときも出力のファイルを一つも作らない。

### Golem の出力

- `tests/fixtures/golem/make.sh` に、角丸の囲みの見本を足す。横組みと縦組みで、実線、破線、点線の枠と、`border-sides` で辺が途切れる枠を持つ。Golem の版は fixture の README に記録する。
- その PDF が通り、72、150、300 dpi のゴールデンを作る。ゴールデンを作る前に、pdftoppm で描いた画像と並べて目で比べ、破線の位置、点の形、角の丸みが合うことを確かめ、プルリクエストに書く（ロードマップの目視検査の項目に「線と破線」を足す）。
- 既存の fixture の五つの PDF を、72、97、150、300 dpi の PPM と 150、300 dpi の PNG で描き、main と同じバイト列であることを確かめる。
- 結合テスト `tests/allocations.rs` に、線の数と破線の数に割り当ての回数が比例しないことを足す（[ADR 0013](0013-fewer-allocations-for-musl-threads.md)）。

## トレードオフ

- 丸い線端を、半円ではなく円板にした。円板の半分は区間の四角形に重なり、塗る多角形の点が増えるが、線端の向きを求める計算が要らず、点線の点（長さ 0 の破線）と同じ形で描ける。
- 破線を、平坦化した線分の上の長さで切る。曲線の長さは平坦化の誤差（1/16 画素）の分だけ短く測られ、長い曲線の上では、破線の位置が真の位置から少しずつずれる。Golem の角丸の四分円は短いので、ずれは画素の値に見えない程度だと見込む。
- 破線の曲線は、キャンバスの外でも平坦化を省かない。省くと破線の位置がキャンバスの大きさに依存し、同じ PDF をページの一部だけ描く使い方が将来入ったときに、画像が合わなくなる。そのかわり、遠い制御点の曲線の破線は、塗りより遅い。
- 周期の下限を装置の空間で決めたので、同じ PDF が、低い解像度ではエラーになり、高い解像度では通ることがある。Golem の点線の周期は枠の太さと間の和なので、太さが 1/16 ポイントを超えれば、72 dpi でも下限を下回らない。
- `2 J`、`j`、`M` を入れないので、Golem がこれらを書き始めたら、shem を直すまで止まる。それは [ADR 0001](0001-scope-golem-contract-and-determinism.md) の版の上げ方の手順どおりである。
- 閉じた部分パスの始点で破線を継がないので、始点を描く要素の途中に置いたパスでは、始点に線端が二つ並ぶ。butt なら見た目は継いだものとほぼ同じで、round なら円板が重なるだけである。
