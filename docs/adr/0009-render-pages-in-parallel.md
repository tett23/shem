# ADR 0009: ページを並列に描く

ステータス: 採択

## 文脈

`shem render` は、今は一つのスレッドで、ページを一枚ずつ描いている（[src/cli.rs:151-188](https://github.com/tett23/shem/blob/702584ad2fa0137d94786b0a6b03c895af86e007/src/cli.rs#L151-L188)）。
[ADR 0001](0001-scope-golem-contract-and-determinism.md) で「描画はスレッドを使わずに一本で行う」と決め、[ADR 0007](0007-png-output-resolution-and-cli.md) でも並列の描画を「実装しないこと」に入れたからである。
決定性を守るのに、スレッドを使わないのがいちばん単純だった。

Golem の見た目の回帰テストは、書籍の全ページを描く。
数百ページの PDF を一つのコアで描くと、CI の時間がページの数に比例して延びる。
CI のランナーや開発者の機械には、複数のコアがある。

ページは互いに独立している。
ページの描画は、文書（`Document`）を読むだけで、ほかのページの結果を使わない（[src/render.rs:386-437](https://github.com/tett23/shem/blob/702584ad2fa0137d94786b0a6b03c895af86e007/src/render.rs#L386-L437)）。
フォントのキャッシュも、ページごとの描画の中に閉じている。
したがって、ページを単位にスレッドへ分けても、各ページの画素は一つのスレッドの中で今と同じ計算で決まる。
スレッドの数や、どのページがどのスレッドで描かれたかは、画素に影響しない。

## 実装すること

### 並列の単位と決定性

- 並列の単位はページとする。一つのページは一つのスレッドで、最初から最後まで描く。ページの中を帯やタイルに分けて並列に描くことはしない。
- [ADR 0001](0001-scope-golem-contract-and-determinism.md) の「描画はスレッドを使わずに一本で行う」を、次のように置き換える。
  - スレッドを使ってよい。ただし、出力の各ファイルのバイト列は、スレッドの数、ページを描く順、スレッドへの割り振りによらず同じでなければならない。
  - スレッドの間で、画素に影響する可変の状態を共有しない。共有するのは、読むだけの文書（`Document`）と、次に描くページの番号を配る数（`AtomicUsize`）だけとする。
- 依存は増やさない。標準ライブラリの `std::thread::scope` でスレッドを作り、仕事の配り方も自前で書く。

### コマンド

- `shem render` に `--jobs <N>` を加える。`N` は 1 以上 1024 以下の整数で、同時に描くページの数の上限とする。
- `--jobs` を省いたときは、`std::thread::available_parallelism` の値（取れなければ 1）とする。
- 実際に作るスレッドの数は、`N` と描くページの数の小さいほうとする。1 なら、スレッドを作らずに今と同じく描く。
- 形の誤った値（0、1025、`x`、二度の指定）は使い方の誤り（終了コード 64）とする。

### 検査と書き出しの順

- 書く前に全ページを検査する手順（[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md)、[ADR 0007](0007-png-output-resolution-and-cli.md)）は変えない。検査も同じ並列の仕組みでページごとに行い、すべてのページの結果がそろってから、ページの番号の順で最初のエラーを報告する。どのスレッドが先に終わっても、報告するエラーは同じになる。
- 検査がすべて通ったら、描画と書き出しを並列に行う。各スレッドは、描いたページをそのまま一時的な名前で書き、名前を変える（[ADR 0007](0007-png-output-resolution-and-cli.md)）。
- 描画か書き出しでエラーが出たら、まだ描き始めていないページは描かない。描き終えたページのファイルは残る（今も、書き出しの途中のエラーでは、それより前のページのファイルが残る）。報告するのは、エラーになったページのうち番号の最も小さいものとする。
- 標準出力に何も書かないこと、エラーの一行の形、終了コードは変えない。

### ライブラリ

- `render_page` と `check_page` の形は変えない。並列化はコマンドの層（`cli`）で行う。
- `Document` がスレッドの間で共有できること（`Sync`）を、コンパイル時の検査（`fn assert_sync<T: Sync>() {}` の呼び出し）で固定する。

### 版と文書

- 画素を変えない機能の追加なので、[ADR 0001](0001-scope-golem-contract-and-determinism.md) の版の上げ方に従ってパッチバージョンを上げる。
- 採択したら、[ADR 0001](0001-scope-golem-contract-and-determinism.md) のステータスを `採択→スレッドの使用は[ADR 0009](0009-render-pages-in-parallel.md)` に、[ADR 0007](0007-png-output-resolution-and-cli.md) のステータスを `採択→並列の描画は[ADR 0009](0009-render-pages-in-parallel.md)` にする（[ADR 0010](0010-diff-images.md) も同時に採択するなら、二つの変更を並べる）。
- 仕様書、README とその翻訳、`--help` に `--jobs` を書く。

## 実装しないこと

- 一つのページの中の並列化（帯やタイルへの分割）。ページの少ない PDF は速くならない。
- 複数のページでのフォントの使い回し。今はページごとにフォントのプログラムを読み直している。並列化とは別の高速化なので、[ADR 0011](0011-speed-up-without-changing-bytes.md) で決める。
- `shem render` の外（ライブラリの利用者）に向けた並列の API。[ADR 0012](0012-parallel-library-api.md) で決める。
- 使うメモリーの上限の管理。同時に描くページの数だけ画像を持つので、メモリーは `--jobs` に比例して増える。大きな解像度で描くときは、`--jobs` で抑える。
- スレッドの優先度や、CPU の割り当ての指定。

## テスト設計

### 決定性

- Golem の四つの fixture を、`--jobs 1`、`--jobs 2`、`--jobs 16`（ページの数より多い）で描き、すべてのファイルのバイト列が同じであることを確かめる。PNG と PPM の両方で確かめる。
- 既存のゴールデン（[ADR 0001](0001-scope-golem-contract-and-determinism.md)）は、`--jobs` の既定値で描いても一致する。CI の三つの環境でも一致する。
- 12345 ページの PDF（[ADR 0007](0007-png-output-resolution-and-cli.md) のテストのもの）の 1 から 64 ページを `--jobs 8` で描き、64 個のファイルがそろい、`--jobs 1` のときと同じバイト列であることを確かめる。

### エラー

- 5 ページの PDF の 2 ページ目と 4 ページ目に範囲の外の演算子があるとき、`--jobs 1` でも `--jobs 8` でも、報告が 2 ページ目のエラーの一行だけで、ファイルが一つもできない。これを 20 回繰り返して、毎回同じであることを確かめる。
- `--jobs 0`、`--jobs 1025`、`--jobs x`、`--jobs` の二度の指定は、終了コード 64 になる。
- `--help` に `--jobs` が含まれる。

### 性能

- 自動のテストにはしない。メンテナーの機械で、Golem の `kanikosen` の fixture（縦組みの小説）を Golem で組んだ PDF を、150 dpi で `--jobs 1` と既定値で描き、時間とコアの数を `docs/benchmarks/` に記録として残す（コミットした記録は変えない）。

## トレードオフ

- ページの単位で分けるので、仕組みは単純で、決定性の議論はページの中に閉じる。そのかわり、ページの数がコアの数より少ない PDF は速くならない。ページの中を分けると、帯の境界をまたぐ覆いの計算を分けることになり、結果が分け方によらないことを示す手間が増える。
- 既定値を「使えるコアの数」にした。出力は `--jobs` によらないので、既定値が機械ごとに違っても画素は変わらない。そのかわり、使うメモリーは機械ごとに変わる。既定値を 1 にする案は安全だが、利用者が毎回 `--jobs` を書かないと速くならない。メンテナーは、既定でコアを使いきってよいと判断した（2026-10-27）。問題があれば `--jobs` で抑えられるからである。
- 検査を描画の前にすべて終える手順を残したので、並列にしても「範囲の外があれば何も書かない」の約束は保たれる。そのかわり、内容のストリームの解釈は二回になる（[ADR 0002](0002-pdf-subset-and-out-of-scope-input.md) のトレードオフと同じ）。
- 描画の途中のエラーで、ほかのスレッドが書き終えたファイルが残る。今の一本の描画でも、途中のエラーの前のページのファイルは残るので、約束の範囲は変わらない。
- 並列の仕組みを rayon などに頼らずに書く。必要なのは「番号を配り、結果を集める」だけで、標準ライブラリで足りる。
